# W3 — Distinct transport and history adapters

Goal: expose explicit start, interrupt, reconnect and disposal behavior with request-scoped cancellation. Prerequisites W1 and W2. Changes: W1's new core transport/POST files and optional Eino package files; new core `test/http_transport_test.dart`, `test/post_adapter_test.dart`; new Eino `test/session_adapter_test.dart`, `test/watch_projection_test.dart`. All test parents are declared in W1. New APIs require no migration, legacy workflow support or flags.

## Common transport invariants

The host supplies routes, identity mapping, fresh headers/auth, authorization decisions, submission input and application actions. The library performs no token persistence/refresh or user-to-session authorization. Validate HTTP status and normalized `text/event-stream` content type before decoding. Do not drain arbitrarily large or never-ending error bodies: abort immediately, classify status and keep only a fixed safe failure record. Never log URLs, query strings, headers, bodies, exception causes or parser actualValue fields.

Each request gets an independent abort trigger before send. Aborting one request must release its connection while another request using the same borrowed client continues. Timeout must abort the underlying send, not merely ignore its response. Initial/control headers have a 15-second deadline; control response bodies have a 64 KiB cap and a 15-second deadline. After watch response headers pass validation, a 5-second initial-baseline deadline runs until the first complete message/state pair commits, including silence or comment-only traffic before its first message. Later pending snapshot pairs each have a 5-second completion deadline. A host may configure other positive finite values. A quiet healthy watch has no arbitrary byte-idle timeout because the server has no heartbeat guarantee. Disconnect detection follows network closure; the host may explicitly reconnect. All transport waits, retries and callbacks carry scoped identity: a session/controller lifetime epoch, a watch-connection generation for GET/pair callbacks, and an individual control-operation identity for each admission/interrupt. A watch-only reconnect invalidates the old GET/pair generation but preserves same-session control operations and their run binding. Session replacement or disposal invalidates all scopes. Stale callbacks cannot publish state.

Dependency gate satisfied: use the verified `https://github.com/mattsp1290/ag-ui.git` commit `691ab5e3846ad5957d1b04a9237167f5496c6232` at `sdks/community/dart`. W1 records the public byte-parser contract and September 10 conformance evidence. Retain shared-client regression tests for failure at line limit+1 while data/comment/unknown-field sources remain open.

Use `SseClient.parseStream` → `EventStreamAdapter.fromSseStream(skipInvalidEvents: false)` with matching data/event limits D and explicit line limit L=D+7 as defined in W1. Close locally owned parser resources on success, error, abort and disposal. Parsing is SDK-owned. The injected `RequestTransport` must satisfy abort-before-headers and abort-during-stream contracts. The default HTTP transport documents that only clients implementing `AbortableRequest` are supported; custom transports must pass the same conformance suite. Do not close a borrowed host client to simulate cancellation.

## Lifecycle

Keep connection phase separate from active run phase. Proposed connection phases: idle, connecting, connected, reconnecting, disconnected, failed, disposed. Proposed run phases: idle, submitting, running, interrupting, completed, failed, paused, interrupted, outcomeUnknown. `paused` is the generic SDK interrupt outcome (execution awaits host action); `interrupted` is the authoritative Eino terminal cancellation status. `busy` errors reject duplicate submissions/control actions; they do not replace an active operation. One controller observes one conversation at a time.

`start` enters submitting before awaiting transport. A session/controller lifetime epoch switch invalidates all previous work and clears its presentation; a same-session watch generation switch affects only observation. Local cancellation aborts HTTP and stops receiving; it does not imply the server interrupted its admitted run. `interrupt` invokes a host-supplied action for the exact active run and stays interrupting until terminal evidence arrives. An accepted interrupt response is an acknowledgement only. If terminal evidence races the acknowledgement, terminal state wins. An interrupt failure leaves the run observable with a safe action failure. No host interrupt capability means the action is unavailable, with local disconnect separately exposed.

`dispose` first marks disposed and invalidates the lifetime epoch, watch generation and all control identities, then aborts all owned request operations, cancels body subscriptions, timers and notifications, closes only owned resources and clears references. It is idempotent. Built-in abort cleanup must complete within two seconds in conformance tests; a custom transport that cannot meet its declared cleanup contract is unsupported. No automatic interrupt is sent during widget/controller disposal.

## Generic caller-owned-history POST

New `AgUiPostAdapter.start(input)` accepts SDK `SimpleRunAgentInput` and a host-supplied endpoint. Encode through public `Encoder.encodeRunAgentInput`; preserve the host's full messages, tools, context, state and forwarded properties. Validate/size-check before sending. Do not derive request history from display rows or introduce a durable session requirement.

A successful response is one stream containing standard AG-UI events. Invoke W1's optional host onProtocolEvent callback in wire order before projecting each event. The host uses these actual events to maintain its next canonical request history, including tool-call arguments/result messages, without decoding twice or extracting history from the restricted view. Retained host history is outside package-owned UI/replay state and diagnostics; document that trust boundary explicitly. Deliver the response-ending event and W2's completed/paused/failed mapping to the reducer before aborting its body stream. On a paused outcome, release this response operation while preserving the paused phase; do not mark success, auto-submit, resume or settle unfinished tools. Subsequent actions remain explicitly host-owned and outside approval/resume routing in this package. EOF without terminal remains incomplete. Retrying a POST can execute the agent twice, so no automatic retry/reconnect of this adapter is allowed, even after timeout. A lost POST response becomes outcomeUnknown if admission cannot be ruled out. The caller chooses a new run/history after reconciling with its own server. Optional interrupt is host-provided; no built-in endpoint or client-side tool settlement is inferred.

## Eino server-owned session adapter

`EinoSessionContract` is a new host interface: build the authorized watch GET for an opaque session identity, build a new-user-message admission request, decode its bounded acknowledgement to an opaque run identity, and build an interrupt action for that exact identity. There is no standard Eino start HTTP route; `transport` only supplies selected embeddable handlers. Routes and acknowledgement schema in the example are explicitly example-owned.

For the example contract, follow selected Eino `examples/minimal-server`: POST new `{message: <text>}` to its session-runs route, receive 202 JSON with `session_id`, `run_id`, `events`, and use `transport.InterruptHandler` for POST interruption. Pinned `decodeRunMessage` confirms the `message` string field; it is an example schema, not the generic SDK `messages` array. Never trust a response `events` URL across origins: the host route builder resolves/validates it or ignores it. Keep remote route values out of logs.

`connect(session)` opens `transport.SessionWatchHandler` and waits for a complete initial snapshot pair. It can observe a session without starting a run. `start(newText)` sends only one new user submission; it never sends old client messages, system prompts, tools or provider-state continuation objects. Do not optimistically insert a fake durable message. A submission indicator is separate from the server-owned transcript until the admitted message appears. If the admission response is lost, mark outcomeUnknown and observe/reconnect the session; never automatically resubmit or assume the newest observed run is this request. A successful bounded acknowledgement atomically binds the exact run ID and immediately reconciles it against the latest complete same-session watch snapshot, including a terminal pair received before the acknowledgement. Do not wait for another update. If there is no complete current snapshot, retain the binding until one arrives; never associate another run merely by recency. Only authoritative status of that ID settles the local submission. Preserve terminal evidence already observed for the currently bound control operation even if a later window omits its run, as one bounded safe outcome record. Before an acknowledgement binds identity, retain only the latest bounded complete snapshot rather than an unbounded history of candidate run outcomes.

A connected session remains watched after a run finishes. WatchBridge emits current snapshots, not `RUN_FINISHED`/`RUN_ERROR`; terminal status comes from `Runs[].Status` for the exact bound run. Display other runs but do not use their historical terminals to terminate the active submission. No resume endpoint is included in v1; reconnecting observation and resuming interrupted execution are different operations.

The selected SQLite observation includes runs referenced by its newest message window plus the active run, not every past terminal. Another client can advance the window while acknowledgement/observation is delayed. A latest snapshot that predates admission may legitimately omit the newly acknowledged run. If acknowledgement binds an ID missing from the latest snapshot, retain submitting/awaiting-observation and request a fresh watch within the existing recovery budget. Only a baseline from a GET initiated after acknowledgement is absence evidence for this case; never treat an old pre-admission baseline as such evidence. If recovery exhausts without a qualifying baseline, expose outcomeUnknown rather than leaving busy forever. If a bound run is absent from a qualifying fresh snapshot and no terminal outcome for it was already retained, set its local phase to outcomeUnknown with outcomeUnavailable, stop waiting for a guaranteed terminal and leave the current session watch usable. Never guess its status from another run, a missing row or message text. New proposed `EinoSessionAdapter.resetSubmissionTracking()` is an explicit host action to acknowledge an unresolved outcome and clear only local run binding/busy tracking; it neither interrupts nor resubmits nor deletes server data. After reset, an explicit new submission may still receive 409 from the server. A host may reconcile through its own API before resetting, but no run-status endpoint is invented or required for the initial shared adapter. Document that bounded current-state observation does not guarantee recovery of an evicted historical terminal.

## Exact watch projection

At the selected Go pin, `agui.WatchBridge.render` emits `MESSAGES_SNAPSHOT` followed by `STATE_SNAPSHOT` on every update, including live-text replacement. Stage messages privately, then atomically commit them with the immediately following valid watch state. Before a complete initial pair, no connected/ready signal is emitted. Drop a staged half-pair on disconnect/session change/dispose. A second messages snapshot without its state pair or an unexpected event is a protocol failure. A lone `{ResyncRequired: true}` state marker is a special resync failure, not a normal state replacement. Never mix a staged snapshot with state from a previous socket generation.

The nested Go state fields have exact exported Go casing, independent of the AG-UI envelope casing:

| State projection | Selected public shape |
| --- | --- |
| Identity | `Watermark.StoreID`, `Watermark.SessionID`, `Watermark.Revision` |
| Window flags | `Exists`, `OmittedOlderMessages` |
| Runs | `Runs[]`: `ID`, `Status`, `ProviderID`, `ModelID`, `LeaseUntil` |
| Tools | `Tools[]`: `ID`, `RunID`, `MessageID`, `Name`, `Status` |
| Live availability | `Live[]`: `Identity` (`ServiceID`, `SessionID`, `RunID`, `MessageID`, `RequestID`, `Attempt`, `Step`), `Available`, `PublicationVersion` |

Decode this shape only in the Eino adapter. Project required identities, safe statuses and availability; discard fields the UI does not need. `Runs`/`Tools` may encode as JSON null for empty slices; normalize null to empty lists. Unknown additive keys are ignored without retention. Missing required keys, wrong types, contradictory session identity, duplicate IDs and unsupported status values yield a content-free incompatible-contract failure. String IDs have finite lengths within the overall budget. Numeric fields are nonnegative exact integers within JavaScript's safe integer range (at most 9007199254740991) on all platforms; reject larger values instead of rounding them. Treat times as optional presentation metadata; never order snapshots by timestamps or leases.

Within one connection generation, allow equal durable revisions because live replacements do not advance them; a lower revision or changed store/session identity requires a fresh watch. Across a fresh connection, accept a new store incarnation and baseline after validating the requested session. Watermarks and publication versions are not wire resume tokens. Different live service identity can accompany a fresh baseline. Do not concatenate `MESSAGES_SNAPSHOT` text with previous text: the server already overlays the current transient prefix. `Live.Available=false` exposes unavailability and uses the server's replacement text; an empty live `MessageID` denotes run-level unavailability and must not create a row. Respect omitted-history flags without inventing pagination or omitted content.

Tools use their durable `ID`. Recognize pending/running/completed/failed/interrupted from the selected Go types. Message removal and final snapshots remove obsolete overlays/tool rows. The current pair is authoritative; never union it with old transcript entries. `Exists=false` and empty messages clear the window rather than reporting auth failure.

## Reconnect and failures

Fresh-watch reconnect is the only supported Eino recovery capability. Cancel only the old watch operation, increment only its connection generation, preserve same-session control-operation identities/bindings, clear staged pairs, mark retained same-session state stale, then GET afresh without `Last-Event-ID` or a cursor query. Manual reconnect resets a bounded recovery budget; success alone does not reset it during a rapid failure loop. Default recovery budget per explicit connect/manual reconnect: one immediate GET and at most two replacement GETs after delays of 250 ms and 1 s, for three total attempts. Inject timer scheduling for deterministic tests. After exhaustion, show disconnected and require host/user action. Session changes clear all retained old-session content immediately.

401 unauthorized and 403 forbidden are distinct non-retryable failures. 404 is unavailable/not-found, 409 is admission conflict, 413/capacityExceeded is non-retryable size failure. Malformed protocol, incompatible shape/content type and other deterministic 4xx do not retry. Network closure, initial-baseline/pair deadline expiry and 502/503/504 watch responses can retry within the same budget. Cancel the initial-baseline timer after the first complete pair; a subsequently quiet healthy connection may remain open indefinitely. ResyncRequired can trigger fresh observation within that budget. Never retry admission/interrupt automatically. Every new GET obtains fresh host-provided credentials, without storing them or implementing refresh. Request-supplied routes must be safely URI-encoded by the host contract.

## Acceptance

Tests prove distinct serialized POST bodies, borrowed versus owned transport lifecycle, independent concurrent request abortion, cancellation before headers/during split frames/during retry and after terminal, error-body abort, 401 vs 403 vs transient classification and maximum retry count. Fault tests inject late old-session callbacks and dropped admission acknowledgements without re-executing a POST. A live race test withholds a 202 admission response until its run's terminal pair has arrived, then releases the response without another watch update; the adapter must settle that exact run and permit the next submission. A second live test reconnects only the GET while the admission acknowledgement is withheld; releasing that acknowledgement still binds/settles the exact run without a second POST. A small-window test lets another client evict the admitted run before acknowledgement/reconnect; assert outcomeUnknown, no false terminal, retained known terminal when available, usable observation and explicit local reset without server mutation. Test initial silent and comment-only streams time out/retry within the budget, while an established complete watch remains healthy idle beyond five seconds. Test host event callback ordering, failure cleanup and absence after disposal. A decoded interrupt-outcome frame must publish paused before body cleanup and send no further POST; Eino interrupted remains separately distinguishable. Parent/child progress must be delivered to the host callback without contaminating parent presentation.

Go-encoded watch fixtures must prove exact casing/null fields, equal-revision live updates, safe-integer overflow rejection, snapshot pairing and half-pair disconnect, empty snapshots, new store/service incarnation, overflow marker, unavailable transient text, stable repeated same-name tool IDs and terminal run/tool states. Reconnect must display each durable message once, restore a paused live prefix when available and never declare unavailable text complete. Run all core and Eino `dart analyze`/`dart test` suites; W5 additionally proves actual HTTP request abortion and browser transport behavior.
