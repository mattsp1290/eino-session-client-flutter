# W2 — Bounded generic event projection

Goal: convert public SDK events into immutable safe presentation state without Eino assumptions. Prerequisite W1. Changes: new core `view_state.dart`, `reducer.dart`, `controller.dart`; new `test/reducer_test.dart`, `test/bounds_test.dart`, `test/privacy_test.dart`, `test/controller_test.dart` under the W1 package parent. No storage, compatibility shim, migration or feature flags.

## State and identity

Maintain ordered messages keyed by SDK message ID and tool activity keyed by tool-call ID, scoped to the controller's current conversation generation. Stable IDs, not names, timestamps, list indexes or text content, determine identity. Two calls to the same tool name remain two rows. Tool results link by tool-call ID; a result message ID does not replace that call ID. Before identity lookup, duplicate checks or ID-less chunk-context resolution, exclude every event and snapshot message with non-null `subagentRunId` from the shared parent projection, using the concrete public SDK types/getters. Ignore dedicated subagent lifecycle events too. Never let a child event create/select a parent active context or settle a parent tool with an overlapping ID. Do not import the SDK's private attribution base class. W1's opt-in host protocol callback still receives original decoded events in wire order, including attribution, for host-owned history; this is separate from the minimal view and does not execute delegated work.

The view contains only user/assistant display text, tool identity/name/phase, safe run/connection phases, content-free failure classification and truncation/unavailability indicators. It stores no raw SDK events or request inputs. No state snapshots, arbitrary metadata/custom/raw payloads, provider state, encrypted reasoning, tool arguments/results, system/developer prompts or raw exceptions enter this default view. Tool result arrival can change activity phase without retaining its content. Display text may itself be user-sensitive and is never logged.

Generic state/custom/reasoning/activity families outside the minimal text/tool/lifecycle projection are deliberately ignored after bounded SDK decoding. Do not implement JSON-patch state reduction here. Host action extensions, richer reasoning display and custom renderers are deferred, not silently implemented by retaining arbitrary maps.

## Reducer rules

- `MESSAGES_SNAPSHOT` authoritatively replaces visible ordered messages and reconstructs tool identity from SDK assistant tool calls and linked tool messages without retaining payloads. After filtering attributed messages, the remaining snapshot authoritatively replaces the parent window; an empty parent projection clears previous messages/tools. Duplicate IDs or incompatible identity/role collisions among the remaining parent records are protocol failures. Hidden roles and unsupported content are excluded; only text content parts from permitted roles survive.
- `TEXT_MESSAGE_START` creates a new display message or reopens the same ID for a later continuation without clearing its snapshot text. Conflicting role/identity fails. `TEXT_MESSAGE_CONTENT` appends the delta exactly once in delivery order. A content event with an unknown ID can establish an assistant message, preserving that stable ID; never invent an ID for uncorrelatable input. `TEXT_MESSAGE_END` ends streaming for that message; it does not terminate the run.
- Snapshot then new delta is the generic contract: the snapshot supplies the baseline and subsequent deltas are new bytes. Repeated deltas are not deduplicated by content, since identical tokens can be legitimate. Generic streams have no guaranteed event IDs or durable replay; no automatic reconnection/re-POST is permitted by the generic adapter.
- Normalize `TEXT_MESSAGE_CHUNK` with explicit ID through the same rules; a missing ID can use only a unique active text-message context in this request. Otherwise fail with an ambiguous-event classification. Tool chunks follow the same rule for tool-call IDs. Do not copy the SDK decoder.
- `TOOL_CALL_START` creates an activity row with parent message ID when available. `TOOL_CALL_ARGS` may mark arguments arriving but discards the bytes. `TOOL_CALL_END` means arguments complete, not tool success; show awaiting result. `TOOL_CALL_RESULT` marks result observed without assuming authority or retaining payload. Out-of-order results with a stable call ID create an unnamed result-observed row that a later start can name without resetting its phase. Missing/ambiguous IDs fail.
- `RUN_STARTED` binds the active request run/thread identity. A second incompatible run in the same generic request is invalid. `RUN_FINISHED` ends this generic response stream, but its SDK outcome determines the execution phase: absent outcome (legacy) or `RunFinishedSuccessOutcome` maps to completed; `RunFinishedInterruptOutcome` maps to proposed `RunPhase.paused` with a fixed “Waiting for host action” status. Paused is distinct from both success and Eino's terminal interrupted status. Discard interrupt IDs, reasons, payloads, results and metadata from view state; do not expose approval/resume actions. `RUN_ERROR` maps to failed. Commit the selected phase before transport cleanup even when the server keeps the socket open. Never copy run-error message/code content directly; map to a fixed safe category. EOF without terminal is disconnected/incomplete, not success. Drop all late events from an invalidated generation.
- On generic response end (completed, paused or failed), unfinished tool activity is shown as unresolved, not inferred successful. Eino-specific authoritative tool status is supplied only by its adapter.

## Bounds and notification lifecycle

Proposed finite defaults: 256 decoded pending events, 1 MiB aggregate pending encoded-equivalent budget, 100 visible messages, 200 tool rows, 256 KiB aggregate display text, 64 KiB per displayed message, 1,048,576 UTF-16 code units per SDK SSE data/event value and 1,048,583 per decoded line (prefixes included), 64 KiB maximum submission text and 2 MiB encoded generic input. Check limits before retaining/replacing data. All configurable limits must be positive, finite and validated. Count UTF-8 display bytes and conservatively charge other strings/records; document units explicitly.

Synchronous reduction avoids a second unbounded event queue. If batching is needed, admission checks both count and byte budget before enqueue. A single latest-state notification slot may coalesce successive state changes, but a terminal state must be delivered before completion/cleanup and must not be overwritten by an ordinary disconnect notification. Keep last run outcome separate from connection phase. Never silently drop token deltas. Input/frame/queue/view overflow aborts the current request and yields `capacityExceeded`, preserving the last internally consistent state. Eino reconnect recovery is explicit and bounded per W3; do not retry deterministic size failures.

Subscribe the controller to input immediately; UI listeners do not control network pause/resume. Removing a listener releases it immediately. Controller disposal invalidates the generation before awaiting input cleanup, cancels pending notification scheduling and releases state after listeners detach. Own no widget resources. Disposal must complete even if no terminal event arrives. No later callback mutates disposed state. A replacement session first discards all old-session data, pending text and errors.

## Acceptance

Reducer table tests prove baseline snapshot + new delta, empty/repeated snapshot replacement, repeated equal token deltas, repeated same-name tools with distinct IDs, result correlation, out-of-order start/result, ambiguous chunks, hidden roles and terminal state. Add public SDK decoder fixtures interleaving parent/child text/tool events with overlapping IDs, attributed snapshot messages and ID-less chunks; assert no parent mutation/collision/context capture from child input and unchanged attributed host callback delivery. Decode real encoded `RUN_FINISHED` frames with absent, success and interrupt outcomes and prove completed/completed/paused respectively, with no retained interrupt payload or automatic action. Tests use SDK types for precise reducer cases; W5 adds real encoded Go frames so these tests are not the sole evidence.

Bounds tests drive exact limit and limit+1 for every count/byte/frame/input cap, a huge unterminated SSE line, slow/missing listeners and event bursts. Assert retained counts/bytes and transport abort count, not merely a thrown error. Controller tests prove listener reentrancy isolation, notification terminal ordering, current-state readability, idempotent dispose and no callbacks afterward. The optional host protocol callback in W1 is an explicit transient host-integration boundary; it is never part of this view, stored replay projection or diagnostic output. Core privacy assertions distinguish the package-owned view from host-owned canonical request history.

Synthetic provider-state canaries in rawEvent, encrypted values, metadata, custom/state events, tool arguments/results and raw errors must be absent from view serialization, replay projections and captured diagnostics. Safe text fixtures are deliberately unrelated to canaries.

Run `dart test` and `dart analyze` from `packages/ag_ui_view_state`. Acceptance: deterministic reducer state, bounded retention, sanitized failures and zero Eino/Flutter imports in core. General JSON-patch support remains excluded.
